## 📐 Мои схемы в CADe SIMU

### Схема 1. Классический пуск двигателя (без ПЛК)

| Компоненты | Обозначение |
|------------|-------------|
| Автомат | QF |
| Контактор | KM |
| Тепловое реле | FR |
| Кнопка "Пуск" | SB1 (NO) |
| Кнопка "Стоп" | SB2 (NC) |
| Двигатель | M |

**Как работает:**  
- Самоподхват через NO контакт контактора.  
- Защита от перегрузки через тепловое реле.  
- Остановка через кнопку "Стоп".

### Схема 2. Управление двигателем через ПЛК (Siemens)

| Входы ПЛК | Выходы ПЛК | Оборудование |
|-----------|------------|--------------|
| Кнопка "Пуск" | Выход на контактор | Контактор |
| Кнопка "Стоп" | Выход на лампу "Работа" | Лампа "Работа" |
| Датчик (опционально) | Выход на лампу "Ошибка" | Лампа "Ошибка" |

**Логика:**  
- ПЛК получает сигнал с кнопок.  
- По программе включает/выключает контактор.  
- Контролирует состояние двигателя и выводит сигналы на лампы.

### Схема 3. Управление двигателем по схеме "Звезда-Треугольник" (Star-Delta) через ПЛК

| Компоненты | Обозначение |
|------------|-------------|
| ПЛК | Siemens S7-1200 |
| Контактор "Сеть" | KM1 |
| Контактор "Звезда" | KM3 |
| Контактор "Треугольник" | KM2 |
| Тепловое реле | FR |
| Кнопка "Пуск" | SB1 (NO) |
| Кнопка "Стоп" | SB2 (NC) |
| Двигатель | M |

**Логика работы:**
1. Пуск: KM1 + KM3 → работа в "Звезде" (снижение пускового тока).
2. Таймер 3-5 секунд.
3. Отключение KM3, затем включение KM2 → переход в "Треугольник".
4. Работа на полной мощности.
5. Остановка: отключение всех контакторов.

**Блокировки:**
- KM3 и KM2 не могут быть включены одновременно (защита от КЗ).
- Пауза между переключениями — 50-100 мс.

## 🤖 Опыт разработки мобильных роботов (ROS, SLAM, AMR)

Параллельно с промышленной автоматизацией я занимаюсь мобильной робототехникой. Это направление показывает мой подход к **интеграции сенсоров, алгоритмов навигации и управления** — навыки, которые напрямую применимы к работе с **промышленными AMR** на заводе.

---

### 🎥 Видео 1 — Движение робота и построение карты (SLAM)

Первое видео показывает, как наш колёсный робот движется в помещении и одновременно строит карту окружения.

| Что вы видите | Что происходит |
|---------------|----------------|
| Робот перемещается | Управление через простой интерфейс (первый прототип) |
| Лидар сканирует пространство | Данные обрабатываются в реальном времени |
| На экране строится карта | Используется **SLAM** для локализации и построения карты |

**Использованные технологии:**
- **ROS** (Robot Operating System) — связь всех узлов системы
- **RPLIDAR** — лазерный сканер для получения данных об окружении
- **SLAM** — алгоритм для одновременного построения карты и определения положения робота

Это наш **первый рабочий прототип**, который подтвердил правильность архитектуры.

---

### 🎥 Видео 2 — 2D-карта с Hector SLAM (без одометрии)

Второе видео показывает результат построения 2D-карты с использованием **Hector SLAM**.

| Что вы видите | Что происходит |
|---------------|----------------|
| Готовая 2D-карта помещения | Построена на основе данных с лидара |
| Робот двигается в реальном времени | Карта обновляется динамически |
| Нет одометрии (колёсных энкодеров) | Используется только лидар — Hector SLAM справляется без неё |

**Что я сделал и проверил:**
- Настроил **Hector SLAM** (без odom) с использованием **RPLIDAR A1**
- Работал с другими типами SLAM:
  - **SLAM Toolbox**
  - **GMapping**
- Проводил симуляции в **Gazebo** (первый шаг перед реальным железом)
